## Why API keys?

Not everything can run a browser login. CLI tools, CI jobs, cron scripts, IoT devices and third-party integrations just want a key. This extension gives them one without adding a second identity system next to Keycloak.

<CardGrid>
  <Card title="Self-service" icon="laptop">
    Users create, list and revoke their own keys in the Keycloak Account Console. Admins get a REST API for everything else.
  </Card>
  <Card title="Standard JWTs out" icon="approve-check">
    Keys are exchanged at the regular token endpoint. Your services keep validating ordinary Keycloak access tokens.
  </Card>
  <Card title="Recognisable keys" icon="list-format">
    Keys start with their client's ID, like `myapp_…`, so a leaked key tells you where it came from at a glance.
  </Card>
  <Card title="Hashed at rest" icon="padlock">
    Only SHA-256 hashes are stored. Keys are shown once, can expire, and can be revoked instantly.
  </Card>
  <Card title="Rate limited" icon="clock">
    Per-minute, hour and day limits per client or realm. Callers get a `429` with `X-RateLimit-*` headers.
  </Card>
  <Card title="Audited" icon="document">
    Key creation, use and revocation emit Keycloak events, so they show up wherever your events already go.
  </Card>
</CardGrid>

## How it works

<Steps>

1. A client calls your API with the key in the `X-API-Key` header.

2. The middleware exchanges it at Keycloak's token endpoint using the `urn:ietf:params:oauth:grant-type:api-key` grant.

   ```bash
   curl -X POST https://auth.example.com/realms/my-realm/protocol/openid-connect/token \
     -d grant_type=urn:ietf:params:oauth:grant-type:api-key \
     -d client_id=my-app -d client_secret=$CLIENT_SECRET \
     -d api_key=myapp_a1b2c3…
   ```

3. Keycloak checks the key's hash, expiry, scopes and rate limit, then issues a normal access token for the key's owner.

4. Your handler gets the decoded claims (`sub`, roles, scopes, `api_key_id`). Results are cached, so Keycloak isn't hit on every request.

</Steps>

## Middleware

Drop-in integrations for the stacks you already run.

<Tabs syncKey="stack">
  <TabItem label="Express">
    ```bash
    pnpm add @emdzej/keycloak-api-keys-express
    ```

    ```ts
    import express from 'express';
    import { keycloakApiKey } from '@emdzej/keycloak-api-keys-express';

    const app = express();

    app.use('/api', keycloakApiKey({
      serverUrl: 'https://auth.example.com',
      realm: 'my-realm',
      clientId: 'my-app',
      clientSecret: process.env.CLIENT_SECRET,
    }));

    app.get('/api/me', (req, res) => {
      res.json({ user: req.auth?.sub, roles: req.auth?.realm_access?.roles });
    });
    ```
